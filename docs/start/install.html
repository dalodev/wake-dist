Install Wake ​

Wake runs on one machine you own, in Docker: the server, the web app, its database and the storage for evidence files. One command installs all of it.

What you need ​

  • Linux, macOS, or Windows with WSL 2 (below), on an amd64 (x86-64) or arm64 machine.
  • Docker, running, with the Docker Compose v2 plugin.
  • curl, and ssh-keygen from OpenSSH 8.1 or newer, which checks the release signature. macOS includes it; on Linux it is the openssh-client package.
  • sha256sum or shasum, which checks each downloaded file against the signed list. Linux and macOS include one of them.
  • Node.js 24 or newer with npm, for the wake CLI. Without them the server still installs, and you add the CLI later.
  • A Git repository and a coding agent: Claude Code, OpenCode, Pi or Codex.

A plan in the repository, written with OpenSpec, Spec Kit or ODD, is optional: you can connect first and let your agent write the plan later. The installer checks what it needs before it writes anything; Install options lists every requirement and option.

Install the server ​

sh
curl -fsSL https://github.com/dalodev/wake-dist/releases/latest/download/install.sh | sh

The command downloads the newest release, checks its signature and installs it into your installation directory. Once Wake answers, the installer also:

  • turns on daily upgrades: every day at 04:17, machine time, it backs up Wake and upgrades the server and the web app (see Upgrade),
  • puts wake-server on your PATH, the command that starts, stops, upgrades, backs up and restores Wake,
  • installs the wake CLI when Node.js 24 or newer and npm are present,
  • remembers this installation, so the wake commands you run on this machine find it by themselves,
  • opens your browser on the page where you create your account.

It ends with a checklist of what it set up and where Wake is running, for example:

text
Wake 2.4.0 installer
  ✓ Docker is running
  ✓ Ports 8080 and 8081 are free
  ✓ Secrets generated in /home/you/wake-server/.env (never printed)
  ✓ Server, web, database and storage started
  ✓ License: Wake Free License, in /home/you/wake-server/LICENSE
  ✓ wake CLI 2.4.0 installed
  ✓ wake-server added to your PATH
  ✓ Daily upgrades on: 04:17, backup first, rollback if unhealthy

Wake is running at http://localhost:8080
  → Your browser is opening. Create your account there.
    Didn't open? Visit http://localhost:8080/sign-up yourself.
  → Then, in your project's git repository: wake setup

Manage it with wake-server start, stop, status, upgrade, backup, restore, accounts, auto-upgrade and install-cli (/home/you/wake-server/wake-server).

A line starting with ! names a step it could not do and the command that does it later, such as wake-server install-cli once Node.js is installed.

Your Wake URL and installation directory ​

Your Wake URL is the address of your Wake: you open the web app there, and the CLI and your agents connect to it. It is http://localhost:8080 by default. The installer's --port option serves it on another port, and --domain serves it at https://<your domain>. Evidence files use a second address that the installer also sets up (http://localhost:8081 by default, https://s3.<your domain> with --domain); you never need to type it.

Your installation directory holds Wake's settings, its backups and the wake-server command. It is ~/wake-server by default; --dir chooses another.

Options go after sh -s --, for example:

sh
curl -fsSL https://github.com/dalodev/wake-dist/releases/latest/download/install.sh | sh -s -- --port 9090 --dir ~/wake

The rest of these docs write <your Wake URL> and <your installation directory>: use your own wherever you see them.

Who can reach it ​

A local installation, the default, answers only on this machine: it listens on 127.0.0.1, so no other computer on your network reaches it. You, your browser and the agents on this machine use it at http://localhost:8080.

For teammates on other machines, install Wake with --domain on a server they can reach. It serves Wake over HTTPS at your domain (see Install options). A local installation cannot be shared through a tunnel of your own: its addresses, including the one evidence files use, stay localhost, and the CLI sends its token only to an https address or to localhost. The free plan allows up to 3 people in all, however many installations you run, and agents never count.

Windows with WSL 2 ​

On Windows, Wake runs inside Ubuntu on WSL 2, Windows' built-in Linux. Follow these steps in order. Each says where to run its commands: in PowerShell on Windows, or in the Ubuntu terminal.

1. Install WSL 2 and Ubuntu ​

Open PowerShell as administrator (right-click Start, then Terminal (Admin)) and run:

powershell
wsl --install

Restart Windows when it asks. Ubuntu then opens and asks for a user name and a password: they are your Linux account, and sudo asks for that password later. To check, run in PowerShell:

powershell
wsl --list --verbose

It lists Ubuntu with 2 under VERSION.

2. Install Docker Desktop ​

Install Docker Desktop for Windows and keep its WSL 2 option on. Open Docker Desktop, go to Settings > Resources > WSL Integration, turn on Ubuntu, and choose Apply & restart. To check, run in the Ubuntu terminal:

sh
docker compose version

It prints Docker Compose version v2.... Docker Desktop must be running whenever you use Wake.

3. Install the tools and Node.js ​

In the Ubuntu terminal:

sh
sudo apt update && sudo apt install -y curl git openssh-client
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.bashrc
nvm install 24

To check, run node --version: it prints v24. and the rest of the version. Install Node.js with nvm, as above, and not with apt: the installer puts the wake command in place with npm install --global, which needs no sudo with nvm.

4. Install Wake ​

In the Ubuntu terminal:

sh
curl -fsSL https://github.com/dalodev/wake-dist/releases/latest/download/install.sh | sh

It ends with the checklist above, including ✓ wake CLI ... installed.

5. Open Wake in your Windows browser ​

Open http://localhost:8080 in your Windows browser; WSL 2 forwards localhost to Ubuntu. If no browser opened by itself, copy the address the installer printed (the one with /sign-up) and create your account there.

6. Connect a repository and run your agent ​

Keep your repositories in Ubuntu's own folders and run your agent from the Ubuntu terminal, so its hooks find wake. In the Ubuntu terminal:

sh
mkdir -p ~/code && cd ~/code
git clone <your repository URL>
cd <your repository>
wake setup

Install your agent inside Ubuntu, following its own instructions, and start it from that folder. Then go on with Your first project.

Daily upgrades ​

Daily upgrades run at 04:17 from Ubuntu's cron, so only while Ubuntu is running. To check that cron runs, in the Ubuntu terminal:

sh
systemctl is-active cron

It prints active. If it prints something else, or systemctl fails, turn on systemd, which starts cron with Ubuntu (see WSL's settings):

sh
printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf

Then run wsl --shutdown in PowerShell and open Ubuntu again. Whenever you want, upgrade by hand in the Ubuntu terminal with wake-server upgrade; see Upgrade.

Where the CLI keeps its token ​

Ubuntu on WSL usually has no keychain service, so the CLI keeps its token in a file only you can read; see Tokens on your machine.

Run it again ​

Running the installer again changes nothing in the installation and opens Wake; the options only apply to a new installation. One machine keeps one Wake: the installer refuses a second installation in another directory and names the existing one.
