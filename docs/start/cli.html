Install the CLI and sign in ​

wake is the command-line program that connects a repository to Wake and that your agent's hooks run. The hooks call it by name, so it must be on your PATH: an alias is not enough.

Install the CLI ​

On the machine where you installed Wake, the installer already installed the CLI if Node.js 24 or newer and npm were present. Check:

sh
wake --version

If it is missing there, wake-server install-cli installs it. On any other machine, such as a teammate's laptop, the same installer installs only the CLI:

sh
curl -fsSL https://github.com/dalodev/wake-dist/releases/latest/download/install.sh | sh -s -- --cli-only

It runs on Linux, macOS, and Windows inside WSL 2 (Windows with WSL 2), and needs:

  • Node.js 24 or newer with npm;
  • curl;
  • the tools that check the download's signature and checksums, as for the server: see What you need.

Before installing, it checks the download against the Wake release key, so a changed file installs nothing. It needs no Docker. It ends with Next: wake login --server <your Wake URL>. To check a download yourself, see Verify a download.

A teammate needs a shared Wake

A CLI on another machine signs in to a Wake it can reach over HTTPS: an installation made with --domain. A local installation answers only on its own machine (see Who can reach it).

Sign in ​

You usually do not need to: wake setup, in Your first project, signs the CLI in for you. Sign in yourself to use the CLI without wake setup, or when Wake asks you to.

In the browser ​

sh
wake login

On the machine where you installed Wake, wake login finds your Wake by itself. On any other machine, name it: wake login --server <your Wake URL>.

  1. It prints a code such as BCDF-GHJK and opens a page of your Wake in the browser.
  2. Sign in to the web app if it asks, check that the code and the machine's name match, and choose the workspace (your personal one unless you pick another).
  3. Choose Approve. The terminal prints Logged in to ... with your email, the workspace's name and its id in parentheses.

Approve only a login you started yourself. The code expires after 10 minutes; run wake login again for a new one. Ctrl-C stops waiting.

  • --no-browser prints the code and the page's address without opening anything, so you can approve it on another device, such as your phone when you are connected over SSH.
  • --workspace <id> signs in to that workspace; the browser offers only it.

A connected repository names its workspace as workspaceId in .wake/config.json. To work in it, sign in to that workspace:

sh
wake login --server <your Wake URL> --workspace <id>

When this machine has no login for it, your agent's session start names this command with the repository's values.

The CLI stays signed in for 90 days. Approving creates a personal access token named wake CLI on <machine>, which expires after 90 days and is kept in your system's keychain (or, without one, in a file only you can read). When it expires, your agent's session start says so and names the wake login command to run again. The token appears on the Tokens screen, linked in the web app's header at the top right; to sign that machine out, choose Revoke on its row and confirm.

Sign in with a token ​

Where no browser can approve a login, such as a script, create a token in the web app: open Tokens, enter a name such as your machine's, choose Create token and copy the secret (Wake shows it only once). Then run wake login --with-token and paste it when asked; it is not echoed. A token piped on standard input works the same way, for example from your password manager's command line, so it never sits in a file or your shell history.

In CI ​

Skip wake login: give the token as WAKE_TOKEN and your Wake URL as WAKE_SERVER, both from the pipeline's secrets:

sh
WAKE_SERVER=https://wake.example.com WAKE_TOKEN="$WAKE_CI_TOKEN" wake sync

The CLI sends WAKE_TOKEN only to the server WAKE_SERVER names. With WAKE_TOKEN set and no WAKE_SERVER, it stops with WAKE_TOKEN is set without WAKE_SERVER; set WAKE_SERVER to the server the token belongs to. When a command would call another server, for example one a pull request wrote into the repository's .wake/config.json, it stops with a line naming both servers and sends nothing.

Update the CLI ​

The server and the CLI update separately. Your server upgrades itself daily, or when you run wake-server upgrade. Each CLI updates itself at the next agent session once its server recommends a newer one, for a CLI installed globally as the installer does, and never in CI. wake upgrade updates it now; on the machine where you installed Wake it upgrades the server first. Set WAKE_AUTO_UPGRADE=off to turn the automatic update off. See Upgrade.
