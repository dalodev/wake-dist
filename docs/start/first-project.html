On this page

Your first project ​

With Wake installed, you create your account and connect a repository. From then on, every agent session in that repository reports its work to Wake. The words this page uses (project, phase, task, session) are explained in Concepts.

Create your account ​

The installer opened the page where you create your account; if you closed it, open <your Wake URL>/sign-up. Choose Create account and enter your name, email and a password. Wake creates your personal workspace and, since it has no project yet, shows Connect your first repository.

The free plan allows 3 people in all, however many installations you run; see Free plan accounts.

Connect a repository ​

Connecting takes one command in the repository, one commit and one sign-in for your agent. In a terminal, go to your repository and run wake setup:

sh
cd ~/code/shop
wake setup

The page Connect your first repository shows the same command, and the browser takes over from there:

  1. wake setup finds your Wake by itself: the repository's own server if it is already connected, else the one the installer recorded on this machine, else the one you signed in to. When none is known, it asks for your Wake URL.
  2. It opens your Wake in the browser and shows a code. With --no-browser it only prints the address and the code, to open them on any device.
  3. In the browser, sign in if needed, check that the code matches the terminal, create a project named after the folder or pick an existing one, and pick your coding agent. The agents installed on this machine are marked.
  4. The terminal and the browser both show each step: signed in, project linked, plan sent with its phases and tasks, agent configured. The terminal ends with ✓ Connected, the command that opens your agent, and a command to commit the new files.

You do not need a plan yet: without one, Wake connects anyway and shows the plan as soon as your agent writes it. A repository with no plan uses OpenSpec, so run openspec init in it before your agent plans. To plan with Spec Kit or ODD instead, run wake init --plan spec-kit or wake init --plan odd; see Planning methods.

Commit the new files, so every clone of the repository is connected. The suggested command stages everything in the repository:

sh
git add -A && git commit -m "chore: connect to Wake"

If you have other uncommitted work, run git status and add only the files Wake wrote instead.

wake setup never commits for you, and running it again changes nothing that is already set up. When a step fails, the terminal names it and the browser shows it failed; fix the cause and run wake setup again: it resumes where it stopped. Ctrl-C while it waits for the browser stops without storing anything.

If you would rather start in the browser, Create the project here first on that page opens the setup wizard (New project). It ends on the same command to run in the repository and shows "Waiting for the first sync" until the plan arrives, then "Plan received" with a link to the Roadmap.

With options ​

Scripts make the choices on the command line instead of the browser:

sh
wake setup --agent claude-code --project shop --workspace <id>

--agent is claude-code, opencode, pi or codex; --project, --name and --workspace are optional. The workspace id is the one wake login prints in parentheses after the workspace's name, or the workspaceId in a connected repository's .wake/config.json. On the machine where you installed Wake, wake setup finds your Wake by itself; on any other machine, add --server <your Wake URL>. It signs in through the browser when needed (in CI, WAKE_TOKEN with WAKE_SERVER skips that), connects the repository and your agent, and ends by listing the commit and the agent sign-in still to do.

Step by step ​

The same steps as separate commands, after signing the CLI in:

  1. Go to the repository: cd ~/code/shop.
  2. Connect it: wake init. It creates the project, named after the folder (--project and --name change that), writes .wake/config.json, gives every OpenSpec task line a <!-- wake:<id> --> marker that keeps its identity, and sends the plan to Wake. It detects whether you plan with OpenSpec, Spec Kit or ODD; --plan <method> chooses it. Plans on the default branch are committed plans; plans on other branches are provisional until they reach it.
  3. Connect your agent: wake connect claude-code, wake connect opencode, wake connect pi or wake connect codex. It adds Wake's MCP server, <your Wake URL>/mcp, to the project's configuration and never writes a token. What else it writes depends on the agent: see its page under Agents and plans.
  4. Commit the files both commands wrote, as above.

Join a teammate's project ​

When a teammate already connected the repository and invited you to their workspace, you need only the CLI and one sign-in:

  1. Open the invitation link they sent and choose Join; see Invite people.

  2. Install only the CLI on your machine:

    sh
    curl -fsSL https://github.com/dalodev/wake-dist/releases/latest/download/install.sh | sh -s -- --cli-only

  3. In your clone of the repository, run wake setup. The repository's .wake/config.json already names the Wake URL. In the browser, choose the workspace you joined and the existing project. Nothing new needs a commit.

  4. Sign your agent in, as the next section shows.

Sign your agent in ​

Sign the agent in to your Wake once, in the browser:

AgentSign in
Claude CodeTrust the folder when Claude Code asks, accept the wake MCP server and install the wake plugin when it offers them, then run /mcp and choose wake
OpenCodeopencode mcp auth wake
PiTrust the project, then pi mcp login wake
CodexTrust the project when Codex asks, review and trust Wake's hooks with /hooks, then codex mcp login wake

The browser asks you to allow the agent. An agent that registered itself with Wake shows an Unverified label: its name is the one it chose, and Wake cannot tell who made it, so allow it only right after you started the sign-in yourself. An agent that publishes its details at a web address shows that address's host instead, for example Published at app.example.com.

What you will see ​

Open your Wake: the Roadmap shows your plan's phases and their tasks. Every agent session in the repository now syncs the plan when it starts and learns which tasks are free and which other sessions hold. Ask your agent for a task with Wake's next command (in Claude Code, /wake:next; each agent's page names its own): it proposes the next task and claims it once you confirm, reports its progress and evidence while it works, and completes it with its verification. When the session ends, Wake releases its claims.

When you edit the plan outside an agent session, run wake sync, or wake watch to sync on every change.

Finish your first task ​

When the agent's work is done, run Wake's done command (in Claude Code, /wake:done; each agent's page names its own). It runs the repository's checks, attaches the evidence and completes the task. Open the task in Wake: its verification, commits and evidence are there; see Task detail.
