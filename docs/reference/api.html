HTTP API ​

The web app and the wake CLI talk to the server over an HTTP API, which your scripts can use too. This page covers the endpoints for workspaces, members, the audit log, tokens and your account.

Before you start ​

Every address starts with your Wake URL. The examples keep it, your token and your workspace's id in shell variables:

sh
WAKE_URL=<your Wake URL>
WAKE_TOKEN=<a personal access token>
WS=<your workspace id>
  • Token: create a personal access token on the Tokens screen, or reuse the WAKE_TOKEN you give the CLI in CI, and send it as Authorization: Bearer <token>. A token belongs to one workspace and sees only that one.
  • Workspace id: wake login prints it, such as Logged in to <your Wake URL> as ana@example.com, workspace Acme (ws_…).GET /v1/workspaces lists the workspaces you can reach.
  • Errors: every error answers { "error": { "code": "…", "message": "…" } }, sometimes with details. A workspace or resource you cannot reach answers 404, the same as one that does not exist.

Browser-session endpoints ​

Some endpoints refuse personal access tokens, so a leaked token can neither create more tokens nor manage people or your account: creating a workspace, invitations, members' roles and removals, tokens, and everything under Your account. They need a browser session, as the web app has; a token gets 403 session_required.

A script can open one: sign in, keep the cookie, and send the session's csrfToken and your Wake URL as Origin with every change. This one works in bash and zsh, with WAKE_URL set to your Wake URL and WS to a workspace id:

sh
printf 'Password: '; read -r -s PASSWORD; echo
CSRF=$(printf '%s' "$PASSWORD" | jq -Rs '{email: "ana@example.com", password: .}' |
  curl -sf -c wake.cookies -H "Origin: $WAKE_URL" -H "Content-Type: application/json" \
    --data-binary @- "$WAKE_URL/v1/auth/sign-in" | jq -r .csrfToken)
unset PASSWORD
curl -sf -b wake.cookies -H "Origin: $WAKE_URL" -H "X-CSRF-Token: $CSRF" \
  -H "Content-Type: application/json" -d '{"name":"build server"}' \
  "$WAKE_URL/v1/workspaces/$WS/tokens"

The password reaches curl on standard input, through jq, which also escapes it, so it never appears in a process list or your shell history.

A change without them is refused with 403 csrf_failed. Each session counts toward the 3 browsers an account stays signed in on; delete wake.cookies when you are done.

Workspaces ​

  • GET /v1/workspaces lists your workspaces, each with its id, name, kind (personal or team) and your role. With a token, only the token's workspace.
  • POST /v1/workspaces with {"name":"Acme"} (1 to 100 characters) creates a team workspace with you as its owner and answers 201 with the workspace. Browser session only. This is the only way to create a team workspace: the web app has no screen for it.

Members and invitations ​

  • GET /v1/workspaces/<workspace>/members lists the members, with the installation's people and peopleLimit.
  • POST /v1/workspaces/<workspace>/invitations with {"role":"member"} (owner, member or viewer) creates an invitation and answers its link once. A workspace has at most 50 pending invitations; past that, 409 too_many_invitations.
  • GET /v1/workspaces/<workspace>/invitations lists the pending ones; DELETE /v1/workspaces/<workspace>/invitations/<invitation id> revokes one.
  • PATCH /v1/workspaces/<workspace>/members/<user id> with {"role":"viewer"} changes a role; DELETE /v1/workspaces/<workspace>/members/<user id> removes a member. The last owner stays: 409 last_owner.
  • POST /v1/auth/sign-up with email, password, name and the link's token (the text after #) as invitation creates an account and joins in one step; the answer adds the joined workspace. A token that is unknown, used, revoked or expired answers 404invitation_not_found and creates no account. Each try counts with the invitation lookups from that address, 10 a minute.

Only an owner, with a browser session, creates or revokes invitations and changes or removes members; anyone else gets 403 owner_required.

Audit log ​

Only owners read the audit log, with a browser session or a personal access token, so scripts can collect it. Members and viewers get 403 owner_required.

sh
curl -sf -H "Authorization: Bearer $WAKE_TOKEN" \
  "$WAKE_URL/v1/workspaces/$WS/audit?limit=100&from=2026-10-01T00:00:00Z&to=2026-11-01T00:00:00Z"
curl -sf -H "Authorization: Bearer $WAKE_TOKEN" -OJ "$WAKE_URL/v1/workspaces/$WS/audit/export"

GET /v1/workspaces/<workspace>/audit answers {"entries": [...], "next": ...}, newest first:

  • limit is 1 to 500, 100 by default.
  • Pass next as before for the next, older page, until it is null.
  • from (included) and to (excluded) are instants with an offset.

GET /v1/workspaces/<workspace>/audit/export downloads the same range oldest first, as wake-audit-<workspace>-<date>.csv with a header row: occurred_at, action, the actor's and the target's id, name and email, subject_id and details (such as the cause of a revoke). A cell starting with =, +, -, @, a tab or a carriage return gets a leading ', so a spreadsheet shows it as text instead of running it as a formula.

Tokens ​

Browser session only.

  • POST /v1/workspaces/<workspace>/tokens with {"name":"build server"} creates a token and answers its secret once. expiresInDays, 1 to 365, changes its lifetime from the default 90. A viewer gets 403 viewer_read_only.
  • GET /v1/workspaces/<workspace>/tokens lists your tokens in the workspace.
  • DELETE /v1/workspaces/<workspace>/tokens/<token id> revokes one.

Your account ​

Browser session only.

  • GET /v1/auth/identities answers whether you have a password and which providers are linked.
  • POST /v1/auth/<provider>/link, where <provider> is github, google, microsoft or oidc, answers the url the browser visits to link that provider.
  • DELETE /v1/auth/identities/<provider> unlinks one; your last way to sign in stays: 409 last_sign_in_method.
  • POST /v1/auth/password with currentPassword and newPassword changes your password. A wrong current password answers 403 invalid_current_password; an account that signs in only with a provider, 409 no_password.
  • POST /v1/auth/sign-out-everywhere revokes every session, token and agent connection of your account, as Sign out everywhere does.
