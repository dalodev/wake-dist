wake-server ​

wake-server manages an installation: it lives in the installation's directory, and the installer puts a command of the same name on your PATH. Run wake-server --help for its usage.

Run wake-server as the user who installed it, never with sudo. If the command is not found, run <your installation directory>/wake-server, or add ~/.local/bin to your PATH (see Troubleshooting).

CommandDoes
wake-server startStart Wake as installed, opening Docker Desktop first on macOS when Docker is not running; waits until Wake is healthy. See Start and stop
wake-server stopStop Wake; containers, volumes, backups and settings are kept
wake-server statusShow the version, the people the free plan counts, the backups, each service's health and the newest release. See Status
wake-server upgrade [--version vX.Y.Z] [--log <file>]Back up, then move to the newest stable release or to vX.Y.Z; roll back, data included, when the new version is not healthy; then keep the newest WAKE_UPGRADE_BACKUPS upgrade backups. See Upgrade
wake-server backupWrite a backup of the database, the evidence files and .env to backups/ while Wake keeps serving. See Back up and restore
wake-server restore <backup>Replace the data with a backup's, after backing up the current data; Wake stops while it runs, and .env is kept. <backup> is a full path or one relative to the current directory. See Restore
wake-server accountsList the accounts and the people the free plan counts. See Free plan accounts
wake-server accounts disable <email>Sign an account out and free its place, keeping its history
wake-server accounts enable <email>Give a disabled account back while a place is free
wake-server auto-upgrade onRun upgrade daily at 04:17 from your crontab, logging to auto-upgrade.log. See Upgrade on a schedule
wake-server auto-upgrade offStop the daily upgrade
wake-server auto-upgrade statusPrint on or off
wake-server install-cliInstall the wake CLI of this version with npm (Node.js 24 or newer), verified

--log <file> appends all of an upgrade's output to the file, first moving a file over 1 MiB to <file>.1.

Exit codes ​

  • 0: done, or nothing to do (such as an upgrade that finds Wake up to date).
  • 1: the command failed and says why, such as Docker not running, a refused backup, a rolled-back upgrade, or a second upgrade, backup or restore while one runs.
  • 2: a usage error, such as an unknown command or option, or a missing argument; the usage is printed.

Environment ​

VariablePurpose
WAKE_DOCKER_TIMEOUTSeconds start waits for Docker Desktop on macOS (default 120)

Settings that change the installation itself, such as WAKE_UPGRADE_BACKUPS, go in its .env; see Installation settings.

The installer ​

install.sh takes the options in Install options and reads these variables:

VariablePurpose
WAKE_BIN_DIRWhere the wake-server command goes (default $HOME/.local/bin)
WAKE_OPEN_COMMANDThe program that opens the browser at the end (default open on macOS, xdg-open on Linux)
