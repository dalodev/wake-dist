Troubleshooting ​

Start with wake doctor ​

In the repository, run:

sh
wake doctor

It checks the connection, the plan method, the plan's text and detail, your login, the server's version, the MCP endpoint, wake on PATH and every connected agent's files. It changes nothing, and ends each failed check with its fix, such as Fix: wake login --server <your Wake URL>. On the machine where you installed Wake, plain wake login finds your Wake URL by itself.

On the machine that hosts Wake, wake-server status shows the version, each service's health and whether Docker runs; see Status.

In the repository ​

The session starts with one Wake: line. Wake is offline, the token is invalid, or you are not logged in. The line says which, and what to run.

Wake: not logged in to <your Wake URL> (workspace <id>); run `wake login --server <your Wake URL> --workspace <id>`, then start a new session. This machine has no login for the repository's workspace, for example when you join a teammate's project. Run the command the line names, then start a new session. <id> is the workspaceId in the repository's .wake/config.json.

wake: the token is invalid, expired or revoked; create one in Wake and run `wake login`. Run wake login again. At a session start the same problem reads Wake: the token for <your Wake URL> is invalid, expired or revoked; run `wake login --server <your Wake URL>`. A token stops working when it expires, is revoked, or when you sign out everywhere.

! Plan text: 2 tasks shortened to fit Wake's limits; the full text stays in the repository. Some tasks have text longer than Wake keeps (Long task text). wake doctor lists each one under the warning, with its file, line and field (title, description or done when). It is a warning, not a failure: wake sync still sends the plan, and says so until you shorten those lines.

A task's Includes and Done when say "The plan does not say…". The task has no indented lines under it in its plan file. wake doctor warns with ! Plan detail: 3 open tasks without a "Done when:" line; add one under each task in its plan file and lists each one as path:line. Add a description line and a Done when: line under each task (see OpenSpec, Spec Kit or ODD), or ask your agent to add them to every open task, then run wake sync. Done tasks and ODD table rows are never listed.

The CLI and the server versions differ. wake login, init, sync, watch and the session context end with one line, and the command still works:

text
wake: wake 2.4.1 is available for this server (you have 2.4.0); run `wake upgrade`
wake: this server needs wake 2.4.0 or newer (you have 2.3.0); run `wake upgrade`
wake: wake 2.5.0 is newer than this server (2.4.0); upgrade the server or run `wake upgrade --version 2.4.0`

Wake checks each server at most once an hour, and stays silent when the server does not answer.

wake: wake 2.4.1 is available (you have 2.4.0); run `wake upgrade`. A newer CLI is released. Without a server recommendation, login, init, sync and watch ask GitHub for the newest release at most once a day. Set WAKE_NO_UPDATE_CHECK=1 to turn it off; it is off when CI is set.

wake: project shop-api is archived; restore it in the web app to sync again. Someone archived the project. Restore it from Archived projects in the web app's project switcher; wake init and wake setup refuse an archived project the same way.

wake: you are a viewer in this workspace, which is read-only; ask an owner to make you a member. Viewers read everything and change nothing; see Roles.

On the server ​

The installer's own messages start with wake:, like the CLI's, and wake-server's with wake-server:; each names what failed and what to run next. A wake: line printed while the install command runs comes from the installer.

The installer stops on a busy port. Pass other ports with --port and --s3-port; see Install options.

wake: Wake is already installed in <dir>: run the installer with --dir <dir> to see it, or remove that installation first. One machine keeps one Wake server, and another directory already holds it. Run the installer with --dir set to that directory, or remove that installation first.

ssh-keygen from OpenSSH 8.1 or newer is needed to verify Wake releases: install it (the openssh-client package on Linux), then .... The installer, wake-server upgrade and wake-server install-cli verify each release's signature with ssh-keygen. Install it, then run the command the line names again.

wake-server: command not found. The installer put wake-server in ~/.local/bin, which is not on your PATH, or you are not the user who installed Wake. Run it as that user, never with sudo. Add export PATH="$HOME/.local/bin:$PATH" to your shell profile (~/.zshrc, ~/.bashrc or ~/.profile) and open a new terminal, or run <your installation directory>/wake-server.

wake-server: an upgrade, backup or restore is running (process <pid>): try again when it finishes, or remove <dir>/.lock if no wake-server command runs. Only one of them runs at a time, and start and stop do not run meanwhile either. Run the command again when the other finishes. Remove the .lock directory only when no wake-server command runs, for example after the machine stopped in the middle of one.

wake-server: not enough free disk for the backup: it needs about <n> MB in <dir>/backups, <m> MB are free. A backup, upgrade or restore stopped before changing anything: the disk holding backups/ is too full. Move older backups off the machine and delete them, or free other space on that disk, then run it again; see Free disk first.

Wake does not answer after a reboot. Docker is not running. Run wake-server start; on Linux, start Docker first. To have it come back by itself, see Come back after a reboot.

A domain installation exits 1 naming DNS and ports 80 and 443. The names do not point at the machine yet, or the ports are closed. The stack keeps running and gets its certificates once DNS is right; see Install on a domain.

An upgrade says it rolled back. The new version was not healthy in time, so the previous one runs again with its data. Check the logs, and see Upgrade.

An upgrade that runs by itself failed. Nothing prints it; read its log. The server's daily upgrade writes auto-upgrade.log in your installation directory, and the CLI's upgrade at an agent session start writes ~/.config/wake/auto-upgrade.log on that machine. See Upgrade logs.

Evidence uploads answer evidence_storage_unavailable. The server has no evidence storage, or cannot reach it. An installation sets it up; a server you run yourself needs the evidence storage variables.

A sign-up answers people_limit_reached. The installation already has the free plan's 3 people. Free a place with wake-server accounts disable <email>; see Free plan accounts.

A sign-up answers sign_up_closed. Sign-up needs an invitation on this server; ask an owner for an invitation link.

Someone reports an Internal error (request id req_...). Find the request in the server's logs by that id; see Find a request by its id.

Sign-in provider errors ​

When a provider sign-in or a link from Account fails, the browser goes back to the screen it started from and shows one of these messages; GitHub stands for the provider. Starting the sign-in again is always safe. See Sign-in providers.

The person readsCodeWhy, and what to do

This email belongs to another Wake account. Sign in to it another way, then connect GitHub from Account.email_takenThe email belongs to a Wake user who signs in with another provider

A sign-in whose state is missing or does not match, such as one opened from an old tab, answers 400 invalid_oauth_state; start it again. The routes of a provider that is not configured answer 404 not_found.
