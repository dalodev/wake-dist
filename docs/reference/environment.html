Server environment ​

The server reads its configuration from its environment. When a value is wrong, it stops at start and names the invalid variables, never their values.

Installation settings ​

An installation keeps its settings in .env, in its directory (mode 0600). The installer and wake-server manage the WAKE_ lines that hold the version, the address, the ports and the generated secrets (such as WAKE_VERSION, WAKE_PUBLIC_URL and WAKE_POSTGRES_PASSWORD); leave those as they are. The lines below are the ones you may add or change. After a change, run wake-server start, which recreates the services with it; upgrades keep .env.

Besides the managed lines, only these have an effect. The other server variables, such as WAKE_LOG_LEVEL or DATABASE_POOL_SIZE, cannot be set in an installation: the installation sets the ones it needs itself and leaves the rest at their defaults.

LineDefaultPurpose
WAKE_UPGRADE_BACKUPS1How many upgrade backups a healthy upgrade keeps, a whole number from 1 to 100; any other value keeps every backup. Read at the next upgrade: no wake-server start needed. See Upgrade backups kept
WAKE_UPDATE_CHECKonoff stops the server's update check (the server's UPDATE_CHECK)
SIGN_UPopeninvitation lets only people with an invitation create accounts. See Sign-up and accounts
SETUP_TOKENWhile the server has no account, only a password sign-up carrying this token creates the first one. A domain install writes it. See The first account
GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRETTurn on GitHub sign-in
GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRETTurn on Google sign-in
MICROSOFT_CLIENT_ID, MICROSOFT_CLIENT_SECRETTurn on Microsoft sign-in
OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET, OIDC_NAMETurn on an OpenID Connect provider

The provider lines mean what they mean for the server, below; an empty value counts as unset. See Sign-in providers.

Server ​

The variables of the wake-server image, for a server you run yourself. An installation sets them itself, from the .env lines above.

Database ​

VariableRequiredDefaultPurpose
DATABASE_URLyesPostgres connection string
DATABASE_POOL_SIZEno10Most database connections the server opens, 1 to 100
DATABASE_CONNECT_TIMEOUT_MSno5000How long a request waits for a free connection, 100 to 60000; past it the request answers 503 service_unavailable with Retry-After: 5
DATABASE_STATEMENT_TIMEOUT_MSno30000Longest a statement runs before the database cancels it (the request answers 503 service_unavailable), 1000 to 600000; migrations are not limited. A session idle inside a transaction is ended after 60 s
MIGRATE_ON_STARTnotrueApply pending migrations at start. See Migrations
WAKE_STREAM_CACHE_PROJECTSno16Replayed projects each of the server's two stream caches keeps in memory, least recently used first out, 0 to 1000; 0 turns both caches off, so every load replays the whole project

Sign-up and sign-in ​

VariableRequiredDefaultPurpose
SIGN_UPnoopenWho creates accounts: open lets anyone sign up; invitation lets only people with a pending invitation, and the server's first account, create one, by password or through any provider (only by password, with the token, when SETUP_TOKEN is set). Any other value stops start-up. See Sign-up and accounts
SETUP_TOKENnoWhile the server has no account, only a password sign-up carrying this token (the setup value of the sign-up link a domain install prints) creates the first one; a provider sign-in cannot. 32 to 256 characters; a shorter value stops start-up. No effect once an account exists. See Sign-up and accounts
OAUTH_MAX_UNUSED_CLIENTSno10000Dynamically registered OAuth clients without a grant before registration pauses, 1 to 1000000; unused ones expire after a day

Sign-in providers ​

Each group turns one provider on: set all of its variables or none. The callback is <PUBLIC_URL>/v1/auth/<provider>/callback. See Sign-in providers.

VariablesProvider
GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRETGitHub
GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRETGoogle
MICROSOFT_CLIENT_ID, MICROSOFT_CLIENT_SECRETMicrosoft work, school and personal accounts
OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET, OIDC_NAMEOne OpenID Connect provider. OIDC_ISSUER is its issuer URL, https (http only on localhost) without a query or fragment; OIDC_NAME is the button's text, 1 to 40 characters without control characters

Evidence storage ​

Evidence file storage on S3, R2 or MinIO. Set the first four together, or none: without them the server starts, and uploads answer evidence_storage_unavailable. See Evidence storage.

VariableRequiredDefaultPurpose
EVIDENCE_S3_ENDPOINTnoThe origin browsers and agents reach: presigned addresses point there
EVIDENCE_S3_BUCKETnoThe bucket, which must exist
EVIDENCE_S3_ACCESS_KEY_IDnoThe server's key, limited to the bucket
EVIDENCE_S3_SECRET_ACCESS_KEYnoIts secret
EVIDENCE_S3_INTERNAL_ENDPOINTnoEVIDENCE_S3_ENDPOINTHow the server itself reaches the storage, such as http://minio:9000 inside a private network; a request that takes longer than 10 s is abandoned and the confirmation answers evidence_storage_unavailable
EVIDENCE_S3_REGIONnous-east-1Signing region (auto for R2)
EVIDENCE_S3_PATH_STYLEnotrueBucket in the path; false puts the bucket in the host name

Updates and logs ​

VariableRequiredDefaultPurpose
UPDATE_CHECKnoonon reads the newest stable release from GitHub at start and every 12 hours and serves it at GET /v1/updates; off makes no request. Any other value stops start-up. See How you hear of a new release
UPDATE_CHECK_REPOSITORYnodalodev/wake-distThe GitHub repository (owner/repo) whose releases the check reads
WAKE_LOG_LEVELnoinfoLeast severe log line written: info, warn or error; empty means info. Any other value stops start-up. See Logs

Web container ​

The wake-web image needs two variables:

VariableRequiredDefaultPurpose
WAKE_API_PROXYyesThe server's address on your internal network, such as http://wake-server:3000; /v1 is forwarded there
WAKE_S3_URLwhen evidence is storednoneThe evidence storage address browsers download from, the server's EVIDENCE_S3_ENDPOINT; its origin joins the page's policy for images. A value that is not an http(s) URL stops the container

The web container answers any Host; your proxy decides which names reach it.
