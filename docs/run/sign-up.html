Sign-up and accounts ​

Who can create an account, and how to manage the accounts with wake-server accounts. On a local install anyone who reaches the server (only this machine) can create an account, up to the free plan's 3 people. A domain install closes sign-up to invitations and gives you a link for the first account. You can close sign-up yourself, and free a place by disabling an account.

The first account ​

A domain install writes these lines to .env and prints https://<host>/sign-up?setup=<token> once:

sh
SIGN_UP=invitation
SETUP_TOKEN=<64 hexadecimal characters>

While the server has no account, only a password sign-up through that link creates one; any other sign-up answers 403 setup_token_required and creates no user, and a first account through a sign-in provider is refused the same way. Once the first account exists the token has no effect. The sign-up screen removes the token from the address bar as it opens, so it stays out of the browser's history.

Lost the link? Build it from the SETUP_TOKEN line of .env. To use this on an installation made before it, add a SETUP_TOKEN of 32 to 256 characters (openssl rand -hex 32) next to SIGN_UP=invitation and run wake-server start before anyone signs up.

Only by invitation ​

Add this line to the installation's .env, then run wake-server start:

sh
SIGN_UP=invitation

The first account of a server without users is still created freely, unless .env also has a SETUP_TOKEN (see The first account), so you can set it before your first sign-up. After that, only someone with a pending invitation creates an account, joining its workspace in the same step.

  • A refused password sign-up answers 403 sign_up_closed; a new account through a sign-in provider is refused the same way and creates no user.
  • Existing users keep signing in, by password or with a linked provider, and keep linking providers.
  • The sign-up screen says that sign-up needs an invitation.

An invitation link works with sign-in providers too: when the provider's sign-in creates a new account, it joins the invitation's workspace in the same step; an account that already exists just signs in and the invitation stays pending. An invitation revoked or used before the sign-in finishes creates no account (invitation_not_found).

Remove the line, or set it to open, and run wake-server start to open sign-up again. Any other value stops the server at start.

Sign-up limits ​

Every new account counts against one budget per client address, 10 an hour, whether it is created by password or through a provider; signing in to an existing account never counts. Past it, password sign-up and GitHub answer 429 rate_limited with Retry-After, and the other providers send the browser back with the error rate_limited.

Free plan accounts ​

The free plan allows 3 people in all for you and your company, however many installations you run; see License. Each installation holds that limit itself: at most 3 active accounts, each used by one person, and each signed in on at most 3 browsers (a fourth sign-in signs out the oldest). Agents, personal access tokens and OAuth clients never count. A fourth sign-up, by password, invitation or sign-in provider, is refused with 403 people_limit_reached and details.limit 3:

text
This installation already has the 3 people the free plan allows; whoever runs it can free a place with `wake-server accounts disable <email>`

Removing someone from a workspace frees no place: their account stays active. Only disabling the account does. Members in the web app shows how many of the 3 places the installation uses. See the License.

sh
wake-server accounts
wake-server accounts disable vera@example.com
wake-server accounts enable vera@example.com

wake-server accounts lists every account, one line each with the email, the name and active or disabled, then People: <n> of 3 (free plan).

  • disable frees a place: the account cannot sign in any more, and its sessions, tokens and connected agents are signed out (the audit log records the revoked tokens with the cause account_disabled). Its tasks, events, memberships and audit entries are kept, and its email stays taken.
  • enable gives the account back while fewer than 3 accounts are active; its old sessions and tokens stay revoked.

Emails are matched as sign-in matches them, whatever their case. Each command runs while Wake keeps serving and prints one line saying what it did; disabling an account already disabled, or enabling an active one, says so and exits 0. An unknown email, or enabling with no free place, exits 1 and changes nothing; a missing or extra argument exits 2 with the usage. They run inside the server's container, so Wake must be running: otherwise they exit 1 naming wake-server start.
