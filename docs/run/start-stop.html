Start and stop ​

sh
wake-server start
wake-server stop

Wake runs in Docker, and its services restart with Docker. When Docker is not running, after a reboot or after Docker Desktop was quit, Wake is down too.

Start ​

wake-server start brings Wake back:

  • On macOS it opens Docker Desktop when Docker is not running and waits up to 120 seconds for it (WAKE_DOCKER_TIMEOUT changes the wait).
  • On Linux, start the Docker service first, for example sudo systemctl start docker.

It then starts Wake as it is installed, pulling and changing nothing, waits until it is healthy and prints Wake <version> is running at <address>. Running it while Wake already runs changes nothing. It also applies changes you made to .env, such as sign-in providers, by recreating the services that use them.

start and stop do not run while an upgrade, a backup or a restore does: they exit 1 saying an upgrade, backup or restore is running. Run them again when it finishes.

Come back after a reboot ​

Wake comes back by itself whenever Docker starts, unless you stopped it with wake-server stop. To have Docker start with the machine:

  • On Linux, enable the Docker service once: sudo systemctl enable docker.
  • On macOS, turn on Docker Desktop's Settings → General → Start Docker Desktop when you sign in.

Stop ​

wake-server stop stops Wake and keeps its containers, volumes, backups and settings. Wake stays stopped, also across Docker restarts and reboots, until wake-server start.

wake-server upgrade, backup and restore need Docker running and say so when it is not.

Remove Wake ​

Removing Wake deletes its data: every project, task, account and evidence file. Keep a backup somewhere else if you may want them back.

  1. Back up, with Wake running, and copy the file off the machine, because step 4 deletes backups/ too:

    sh
    wake-server backup

  2. Turn off the daily upgrades, which removes Wake's line from your crontab:

    sh
    wake-server auto-upgrade off

  3. Stop Wake and delete its containers and data, from your installation directory:

    sh
    cd <your installation directory>
docker compose down -v

    Add --rmi all to delete Wake's images too.

  4. Delete the files Wake installed:

    • your installation directory, with its settings and backups;
    • wake-server on your PATH, ~/.local/bin/wake-server unless you set WAKE_BIN_DIR;
    • the CLI's settings, ~/.config/wake/ (or $XDG_CONFIG_HOME/wake/).

  5. In each repository you connected, remove what wake connect added, once per agent:

    sh
    wake disconnect claude-code

    The agents are claude-code, opencode, pi and codex. Delete .wake/ from the repository if you no longer want its Wake settings.

  6. Remove the CLI, on every machine that has it:

    sh
    npm uninstall --global @wake/cli

    Its token stays in your system's keychain under the service wake; delete it there, for example in Keychain Access on macOS.
